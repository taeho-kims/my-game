# Game Brief: 슬라임 노다지

**One-sentence pitch:** 영웅을 하늘에서 떨어뜨려 슬라임을 쓸고, 커서로 전리품을 쓸어 담아 상자를 터뜨린 뒤, 그 골드로 영웅단을 키워 다시 출격하는 짧은 런형 수집 게임.

## Core loop
- 클릭한 자리에 영웅(기사·궁수·광전사)을 강하시킨다. 착지 충격을 주고, 이후는 자동으로 슬라임을 처치한다.
- 커서 자석으로 떨어진 코인을 상자에 쓸어 담는다. 많이 모을수록 상자 등급이 오른다(나무→구리→은→금→수정).
- 제한 시간(기본 24초)이 끝나면 상자가 터진다. 기본 골드는 모은 양 × 등급 배율이고, 쏟아진 전리품을 마지막 수확 시간(5초)에 다시 주우면 보너스 골드가 더해진다.
- 골드로 스킬 트리(16노드)를 올리고 재출격한다. 슬라임은 판마다 `1.07^판 수`만큼 강해진다.

## Player goal & fail state — what "working" looks like
- 목표: 한 판 안에 더 높은 상자 등급을 채우고 마지막 수확까지 챙겨 골드를 최대화하고, 트리를 키워 최고 기록을 갱신한다.
- 실패: 하드 실패는 없다. 시간이 끝나면 항상 개봉하고, 못 채우면 낮은 등급·낮은 배율을 받는다. 수확에서 못 주운 전리품은 보너스만 잃는다. "작동함" = 한 판이 개봉·수확·정산으로 끝나고, 골드(기본 + 수확 보너스)가 트리 업그레이드에 반영되어 저장된다.

## MVP — what must exist to be the game
- 영웅 강하 + 착지 충격 + 기사 자동전투 (손맛의 핵심)
- 슬라임 스폰/이동과 코인 드롭, 판마다 스케일 `1.07^판 수`
- 커서 자석 코인 수집 + 상자 5등급과 배율 (프로토타입 `TIERS` 값 그대로)
- 시간제 한 판 + 상자 개봉 연출 + 마지막 수확(쏟아진 전리품 다시 줍기, 5초) + 정산 화면
- 스킬 트리 16노드 + 골드 소비 + 저장 (프로토타입 `NODES` 값 그대로, 데이터 파일로 분리)
- 궁수·광전사 영웅 타입 + 숫자키 1·2·3 선택 (핫바)
- 트리가 해금하는 이벤트 4종: 황금 슬라임, 슬라임 비, 보물 고블린, 대왕 푸딩

## Out of scope — not building this
- 1단계(MVP)에서는 2단계 기능(여러 맵, 맵별 보스, 상점, 장비 강화, 카드, 도감)을 만들지 않는다. 확장 설계 원칙만 지킨다.
- 수치 재밸런싱, 신규 영웅·노드·콘텐츠 (포팅 단계에서는 프로토타입 값 유지)
- 모바일·터치 지원, 멀티플레이, 클라우드 세이브, 다국어
- 배경음악 (프로토타입의 합성 효과음 수준만)

## Build order
1. 강하 + 착지 충격 + 기사 자동전투 + 커서 자석 수집: 손맛부터 검증
2. 상자 등급·배율 + 시간제 한 판 + 개봉 + 마지막 수확 + 정산
3. 스킬 트리 + 저장 + 판마다 스케일
4. 궁수·광전사 + 핫바
5. 이벤트 4종

## 단계 계획
1. **1단계 — MVP:** 원작(Reference game)과 비슷한 루프·구조로 위 7개 MVP를 완성한다. 이름·아트·콘텐츠·수치는 이 프로젝트의 것을 쓴다.
2. **2단계 — 확장:** 여러 맵과 맵별 보스, 상점, 장비 강화, 카드, 도감. 지금은 만들지 않는다.
3. **3단계 — 차별화:** 플레이해 보고 차별점을 정한다. 후보: 상자 등급·배율을 중심에 둔 런 구조(판마다 상자 도박/선택 요소).

## 확장 설계 원칙 (1단계부터 지킨다)
- **저장 데이터:** 버전 필드와 버전별 마이그레이션 함수를 둔다. 시스템별 하위 키(`meta`, `skill_tree`, 이후 `maps`·`equipment`·`cards`·`collection`)로 나눠, 새 시스템은 자기 키만 추가한다. 없는 키는 기본값으로 채우고, 모르는 키는 지우지 않고 보존한다.
- **판 결과 처리:** 판이 끝나면 결과를 데이터 객체 하나(`RunResult`: 맵 id, 기본 골드, 수확 보너스, 상자 등급, 처치 수, 보스 처치 여부, 드롭 목록)로 만들고 시그널로 내보낸다. 보상 적용은 결과를 받는 처리기들이 나눠 맡아, 상점·장비·카드·도감은 처리기를 추가하는 방식으로 붙인다.
- **맵 구성:** 필드 크기, 스폰 표, 슬라임 종류, 이벤트, 보스, 배경을 맵 데이터 파일(맵 id별)로 둔다. 1단계는 맵 하나지만 코드는 맵 데이터를 받아 동작하고 특정 맵을 하드코딩하지 않는다.
- **능력치:** 최종 능력치는 출처별 보정치(스킬 트리, 이후 장비·카드)를 합산해 계산한다. 1단계의 출처는 스킬 트리 하나다.

**Who it's for / what they feel:** 짧은 판을 반복하며 영웅단을 키우는 증분·방치형 팬. 떨어뜨리고 쓸어 담을 때의 묵직하고 쫀득한 타격감이 최우선 품질 목표.

**Art & audio direction:** 8×8 도트 스프라이트를 2배로 키운 픽셀아트(640×360 정수 배율, 프로토타입의 공간 값은 1280×720 기준이라 0.5배로 옮김), 초록 들판과 목재 UI, 8비트 스퀘어/트라이앵글 효과음.

**Reference game:** When Chests Rain Tons of Loot (LeenGameDev, Steam): 강하→수집→상자 폭발→스킬 트리 루프의 원본. 이 루프 구조만 참고하고, 이름·아트·콘텐츠·수치는 이 프로젝트의 것(슬라임 노다지 프로토타입)을 쓴다. 2순위 참고: Vampire Survivors의 자동 전투와 판 끝 성장.
